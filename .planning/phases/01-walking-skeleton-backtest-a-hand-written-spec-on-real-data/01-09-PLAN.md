<objective>
Close the determinism contract on two machines, wire every guard into one CI pipeline, and add the
plot that stays outside the hash.

Purpose: success criterion 2 says byte-identical on two machines, and a same-machine test cannot
establish that — a hash that silently includes a hostname, a path or a locale-dependent format
passes locally forever. Success criterion 6 says a test fails the build on a float in a money
field, and a test that is never run by CI does not fail any build. This plan makes both claims true
where they are claimed.
Output: a recorded reference hash reproduced on a second machine, and one pipeline that runs every
guard this phase built.

  <how-to-verify>
Success criterion 2 is a two-machine claim and no single-machine test can close it.

**Read what is being claimed before running it.** ROADMAP success criterion 2 says "byte-identical
output". What this phase delivers, deliberately, is **byte-identical canonical result bytes and
hash** — the `hash.txt` files must match exactly; the `.parquet` files may differ, because their
footers embed the writing library's version string. That is a semantic reproducibility contract,
and it is the right one: forcing literal artifact-byte equality would mean pinning Parquet writer
versions across every machine and normalising file metadata, so the contract would break on a
routine dependency bump while telling you nothing about whether the *results* changed.

The narrowing must not be absorbed silently. Two hashes matching is a real and sufficient result
for this phase — approve on it. But record in ADR-0005, in one clearly-headed paragraph, that the
delivered contract is narrower than the ROADMAP wording, and state in the plan SUMMARY that
**ROADMAP success criterion 2 is currently overstated relative to what Phase 1 ships and a human
should decide whether to amend its wording to "byte-identical canonical result bytes and hash".**
That is a roadmap edit, not a plan edit, which is why it is surfaced rather than made here.

On machine A, run the reference backtest and record its hash:

```
uv run --project engine backtest --symbol BTCUSDT --spec strategies/sma-crossover.json \
  --from 2024-03-01 --to 2024-03-31 --out runs/reference
cat runs/reference/hash.txt
```

Then on a genuinely different machine — a second developer machine, a CI runner, or the
devcontainer on different host hardware — check out the same commit, initialise the submodule,
point `CATALOG_URI` at the same shared catalog, and run the identical command.

If the developer took Option TRIM from plan 01-07's `<scope_option>` and there is no shared
object-store catalog, ingest the tracer's one-month range independently on the second machine
instead of pointing at a shared one. That is more setup and a stronger result — it proves the
ingest is deterministic as well as the backtest — but say in ADR-0005 which of the two routes was
used, because "same catalog bytes" and "independently reproduced catalog bytes" are different
claims and only one of them was tested.

**Approve** if the two `hash.txt` strings are identical. Do not compare the `.parquet` files; they
are outside the contract by design and a byte difference there is expected, not a failure.

**Reject** if they differ. Do not adjust the canonical form to make them match without first
finding out *which* field diverged: the divergence is the finding, and a canonical form quietly
widened until two machines agree has thrown away the property it was measuring. Diff the two
canonical byte strings, name the differing field, and fix that field.

On approval, write the reference hash, the exact command, the commit SHA, the submodule SHA and
both machines' descriptions into `docs/adr/0005-reproducibility-contract.md`. This recorded hash
is the reference Phase 2's acceptance gate reproduces against, which is why D-18 rates the
canonical form costly to change — every hash recorded from here on is invalidated by a change to it.
  </how-to-verify>
  <resume-signal>Type "approved" with both hash strings pasted, or paste the two differing hashes and the name of the field that diverged.</resume-signal>
