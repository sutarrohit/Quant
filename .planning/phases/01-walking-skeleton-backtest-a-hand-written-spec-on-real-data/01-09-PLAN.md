<objective>
Close the determinism contract on two machines, wire every guard into one CI pipeline, and add the
plot that stays outside the hash.

Purpose: success criterion 2 says byte-identical on two machines, and a same-machine test cannot
establish that — a hash that silently includes a hostname, a path or a locale-dependent format
passes locally forever. Success criterion 6 says a test fails the build on a float in a money
field, and a test that is never run by CI does not fail any build. This plan makes both claims true
where they are claimed.
Output: a recorded reference hash reproduced on a second machine, and one pipeline that runs every
guard this phase built.
</objective>

  <action>
Audit `engine/canonical.py` against every field RESEARCH.md verified as varying per process on the
engine's result object — machine id, instance id, run id, run start, run finish — plus the output
path and the hostname. Assert their absence by searching the produced canonical bytes for each
name and each runtime value, not by reasoning about the serializer. A hash that includes one of
these still passes a same-second same-machine comparison, which is exactly why this must be an
explicit negative assertion rather than a same-machine repeat.

Make every format decision explicit rather than ambient: decimal string form, timestamp format,
and key order are all set by the serializer. Anything left to a locale, a timezone or a default
repr is a machine difference waiting to happen, and Test 3 pins that down.

Add Test 6 as the standing explanation for why the hash is not over file bytes. Someone will
eventually propose hashing the Parquet files because it looks simpler; a passing test showing the
files differ while the data does not is a better answer than a comment.

Create `engine/cli/plot.py` with `render_plot(equity, out_path)` producing a PNG for eyeballing,
and wire a `--plot` flag that renders **after** the hash is computed and written. D-20 puts the
plot outside the contract, and rendering after hashing makes that structurally true rather than
merely intended. The PNG is gitignored by plan 01-01. No web stack, no HTML report, no server —
Phase 4's web app reads the same Parquet.

Extend `trial_recorder` to cover the two exit paths the tracer's version does not: an exception
during artifact writing after the engine finished, and a keyboard interrupt. Add an `aborted`
status distinct from `crashed` so an interrupted run is distinguishable from a failed one. Leave
D-15's known ceiling exactly where it is — a hard kill still loses the row — and keep the recorded
`ponytail:` comment naming the write-ahead upgrade path that Phase 8 will need anyway. Do not build
write-ahead here; CONTEXT.md defers it deliberately and building it now would be scope the phase
did not ask for.

Assert the run output directory holds exactly the three D-19 artifacts. A fourth file appearing
means someone added a manifest, and the manifest is Phase 2's job.

  <action>
Write `.github/workflows/ci.yml` around the single entry point D-08 specifies:
`turbo run test lint check-types`. Do not add a parallel set of per-package CI steps beside it —
the whole point of one pipeline is that what a developer runs locally and what CI runs are the same
command.

The image needs Node, pnpm, Python 3.13 and a Rust toolchain, and D-08's own planner note warns
this makes for a slow cold image. Cache three things, keyed independently: the pnpm store keyed on
the lockfile; the uv cache keyed on the engine lockfile; and the Rust build directory plus cargo
registry keyed on the submodule commit SHA. The submodule SHA is the right key because the pin
only moves deliberately, so the Rust cache stays warm across every ordinary change. Check out the
submodule shallow at the pinned commit rather than cloning its full history.

Size the job timeout against the measured cold-build number recorded in ADR-0002 rather than
guessing, and record in that ADR what the first cached and uncached CI runs actually took, so the
next person changing this has two more real numbers.

Confirm before editing `turbo.json` whether it needs editing at all. The existing task graph
already wires `lint`, `check-types`, `test` and `build` with the dependency shape D-08 asks for,
and those tasks are package-type agnostic. If the four workspace members expose matching script
names, the correct change to `turbo.json` is none — record that finding rather than adding
configuration to look thorough. The one change that may be genuinely needed is declaring the
generated output directories as task outputs so turbo caches the codegen step.

The pipeline must run the money guard and it must not be skippable: success criterion 6 says a test
fails the build if a float reaches a money field, and a guard that CI does not run fails no build.
It runs as part of the engine package's default test task, so nothing special is needed — but
assert that by checking the pipeline's own log for the guard test having executed, not by assuming
the glob picked it up.

The purity job from plan 01-08 stays a separate workflow. It deliberately builds no Rust and must
not inherit this pipeline's toolchain setup, because an environment with the engine installed
cannot prove the absence claim it exists to prove.

```

  --from 2024-03-01 --to 2024-03-31 --out runs/reference
cat runs/reference/hash.txt
```

Then on a genuinely different machine — a second developer machine, a CI runner, or the
devcontainer on different host hardware — check out the same commit, initialise the submodule,
point `CATALOG_URI` at the same shared catalog, and run the identical command.

**Approve** if the two hashes are identical strings.

**Reject** if they differ. Do not adjust the canonical form to make them match without first
finding out *which* field diverged: the divergence is the finding, and a canonical form quietly
widened until two machines agree has thrown away the property it was measuring. Diff the two
canonical byte strings, name the differing field, and fix that field.

both machines' descriptions into `docs/adr/0005-reproducibility-contract.md`. This recorded hash
is the reference Phase 2's acceptance gate reproduces against, which is why D-18 rates the
canonical form costly to change — every hash recorded from here on is invalidated by a change to it.
