Wire ONE path through every layer, end to end. No second symbol, no second interval, no batching,
no configurable fill model, no plot. Real error handling on the single path.

**Ingestion leg — `engine/data/binance_vision.py`.** `download_klines(symbol, interval, date)`
fetches the daily kline archive and its checksum sidecar over HTTPS from the public bulk-data
host. `verify_checksum(archive_path, checksum_path)` computes the SHA-256 of the archive and
compares it against the published digest, raising `ChecksumMismatch` on any difference. The
mismatch path exits non-zero and does not ingest — D-25 is explicit that silently accepting
corrupt market data is how a backtest lies, and there is no fallback to an unverified copy.
`parse_kline_row(row, bar_type, ...)` builds one bar from one CSV row.

Detect the timestamp unit **per file, from the digit count of the raw open-time value** — 13 digits
means milliseconds, 16 means microseconds — never from a global constant and never from the date in
the filename. RESEARCH.md proved by live fetch that the bulk files silently switched units at
2025-01-01 with no schema version marker, no header change and no filename change, so a loader
that assumes one unit misdates every bar from a boundary-crossing ingest without ever raising.
This tracer's date range sits entirely inside the millisecond era on purpose — the boundary itself
is plan 01-07's problem — but the detection goes in now, because retrofitting it after bars are
already in the catalog means re-ingesting everything.

Set the bar's event timestamp to the row's **close** time, per D-24, and set the initialisation
timestamp to the same value. This is the convention that cannot look ahead.

Construct prices and quantities from the CSV's decimal strings directly. Do not route a monetary or
quantity value through `float()` at any point; the engine's own string constructors parse the
decimal exactly, and the test-fixture helper in the vendored checkout that uses the float
constructor is acceptable for test data and not for a production loader.

**Catalog leg — `engine/data/catalog.py`.** `open_catalog(path)` opens the parquet catalog at a
local path for this tracer — the object-store backing of D-23 is plan 01-07's expansion and is a
constructor argument change, not an architectural one. `write_bars` and `write_instruments`
persist the parsed bars and the instrument definition the venue needs. Fetch the instrument from
the exchange's public instrument loader rather than hand-declaring precision filters: it populates
the real maker and taker rates that the fee model reads, so there is nothing to guess.

**Pure leg — `engine/dsl/bars.py` and `engine/dsl/evaluator.py`.** `PlainBar` is a frozen dataclass
with `open`, `high`, `low`, `close`, `volume` as `Decimal` and `ts_event` as `int` nanoseconds.
`DslEvaluator(spec)` consumes `PlainBar` objects one at a time and returns a `Signal` enum value.
It computes both simple moving averages itself over its own bounded deque of closes. It imports
only the standard library, `engine.dsl.spec` and `engine.money`. Nothing under `engine/dsl/` may
import the trading engine, and no comment or docstring under that directory may name the trading
engine's module either — the purity gate is a bare recursive content grep over the directory, so a
comment mentioning the module makes the gate report a violation that does not exist. Put the
explanation in `engine/README.md`, outside the grepped path.

**Adapter leg — `engine/adapters/dsl_strategy.py`.** `DslStrategy` subclasses the engine's strategy
base, subscribes to the configured bar type on start, and on each bar converts the engine bar into
a `PlainBar` and calls the evaluator. All decision logic lives on the evaluator side; the adapter
only translates and acts. On an entry signal it submits a market buy sized from the spec when flat;
on an exit signal it closes the position when long; on stop it closes everything.

This is the only non-test module that imports **both** the evaluator and the trading engine, and
`SIM-04` is structurally true because of that, not because of a test. Read the invariant precisely:
it is *not* "only one module in the engine may touch the trading engine". Three other modules in
this very task must import it — the catalog needs the parquet catalog type, the bulk loader
constructs bars, and the CLI runner configures the backtest node — and none of them is a violation.
FOUND-06 says `DslStrategy` is the only file importing both `DslEvaluator` and the trading engine,
and that is what makes the adapter the single swap point when paper and live arrive in Phase 5. The
two checks that actually encode this are in the verify block, and plan 01-08 owns their CI form:
(a) nothing under `engine/dsl/` references the trading engine at all, and (b) among non-test
modules that import the trading engine, exactly the adapter also imports the evaluator.

**Runner leg — `engine/cli/backtest.py`.** `run_backtest(...)` builds the run configuration from
the catalog path, instrument, bar specification and the parsed date range, configures one venue as
a spot cash account, and runs it. Leave the fill model at the engine's parameterless default and
the fee model at the maker/taker default. Do not configure a slippage or partial-fill model: every
alternative takes a random seed, and any randomness source at all makes "byte-identical on two
machines" depend on matching the RNG algorithm and seed across both. Realistic fill simulation is
Phase 2's requirement, and the correct Phase 1 choice is the model with no randomness to pin.

Extract the equity curve and trade list through the engine's own report generators, not by walking
the cache or by calling `to_dict()` on domain objects. One position field the engine emits is a
raw float where every other money-shaped field is a decimal string, and the engine's own report
generator deletes that column before returning — going through the report generators inherits that
fix instead of re-discovering it.

Write `strategies/sma-crossover.json` as the first hand-written spec per D-26: two simple moving
averages, cross up to go long, cross back to go flat. Deliberately minimal — it exercises indicator
state, entry, exit, sizing and fills, and its trade list is short enough to check by hand against
the bars. Do not extend the DSL beyond what this spec needs; CONTEXT.md records the developer
considering a richer strategy and reverting to keep the surface bounded.

Add a `[project.scripts]` console-script entry so `uv run backtest` resolves, and expose it through

Create `engine/canonical.py`. `canonicalize(trades, equity)` produces a deterministic byte string:
sorted keys, decimal strings for every monetary and quantity value via `to_canonical_str`, a fixed
timestamp format, and rows in a defined total order — equity by timestamp ascending, ties broken by
the catalog's original row index so the order is stable rather than merely usually-stable.
`EXCLUDED_FIELDS` is an explicit frozen set naming every field that must never enter the hash:
machine id, instance id, run id, run start, run finish, output path, hostname. RESEARCH.md
verified each of these is present on the engine's result object and each varies per process, so
including any one of them makes the two-machine claim false while still passing a same-machine
same-second test. `reproducibility_hash(canonical_bytes)` is the SHA-256 hex digest.

Hash the canonical re-serialization of the data, never the Parquet file bytes. The Parquet footer
embeds the writing library's version string, so two machines on different patch versions produce
byte-different files holding identical data — a false determinism failure that would send someone
hunting a bug in the engine.

State the consequence honestly in the module docstring rather than leaving it implied: **what this
phase delivers is byte-identical canonical result bytes and hash, not byte-identical artifact
files.** ROADMAP success criterion 2 says "byte-identical output", which reads wider than that. The
narrowing is deliberate — a semantic reproducibility contract is the stronger engineering choice
here, because pinning Parquet writer versions to make the file bytes match would make the contract
break on a routine dependency bump while telling you nothing about whether the *results* changed.
Plan 01-09 owns raising the wording mismatch for a human decision; this module owns saying plainly
which of the two it implements.

Extend `engine/cli/backtest.py` to write the D-19 minimal artifact set into the output directory —
`trades.parquet`, `equity.parquet`, `hash.txt` — and nothing else. No manifest and no copied spec:
CONTEXT.md records that ceiling deliberately, and Phase 2's reproduce-a-published-backtest gate is
where the full input manifest gets built properly. Record the ceiling as a `ponytail:` comment at
the write site so the deferral is tracked rather than forgotten.

Wrap the entire run in `trial_recorder` so the trials write happens on completion and on crash

path that skips the write: completion, an exception anywhere inside, and a keyboard interrupt all
leave exactly one row (plan 01-09 adds the `aborted` status for the last of these).

Success criterion 5 says every backtest including throwaway ones has *already* written a row, and
that is what this delivers for every run. It does not, and cannot, cover a malformed CLI

no `params_hash`, and are correctly absent from the denominator rather than missing from it. Say
so in the entry point's docstring so the distinction survives contact with a later reader.

simulation and not an expected return. Phase 1 numbers will be read by the person who wrote them
at a point where the cost model is still Phase 2 work, and a number shown without its assumptions
is the most reliable way to fool the one person who most needs not to be fooled.
